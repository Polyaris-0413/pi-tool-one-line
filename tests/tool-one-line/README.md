# Tests

Two tiers: a fake runtime (fast, no credentials) and a real `pi` in a pseudo
terminal (slow, calls the model).

```bash
node run-all.cjs                       # fake runtime, a few seconds
node run-all.cjs --tui                 # + suites A/D/P in a real TUI
node run-all.cjs --tui --with-reload   # + suite L (session reload)
```

Non-zero exit code means something failed. Every suite prints its own `PASS` /
`FAIL` lines; `run-all` also treats the words `FAIL` or `MISMATCH` in the output
as failures.

## Tiers

### `harness/` — fake runtime

The harness copies the extension and itself into `<repo>/tmp/harness-run/` with
junctions to `jiti` and `@earendil-works/pi-tui` (resolved from the global `pi`
installation, or `PI_PACKAGE_ROOT`), because Pi loads extensions through jiti.

| File | Checks |
| --- | --- |
| `thinking-only.mjs` | message shapes that render zero rows, and the ones that keep one blank line |
| `user-message.mjs` | a user message stays one solid block: blank lines keep their background; empty decorations still collapse |
| `segments.mjs` | segments split on assistant text; live and replayed state agree |
| `streaming.mjs` | calls are attributed while streaming, so no placeholder row appears first |
| `expand-levels.mjs` | level-2 expansion replaces the type label with the content, for leaders, non-leaders and thinking rows alike |
| `turns.mjs` | one turn's trailing thinking is not attached to the next turn |
| `repro.cjs` | clicking a summary cannot recurse through invalidation |
| `lastcomponent.mjs` | built-in renderers get their own `lastComponent` back |
| `fuzz.mjs` | 40 seeded event sequences: summary counts match expanded rows, live state matches replay |

### `tui/` — real `pi` in a pty

Each suite spawns `pi -e ../../extensions/tool-one-line.ts` with
`PI_CODING_AGENT_DIR` pointing at `tmp/tui-home`, an isolated config directory
containing only a minimal `settings.json` (`hideThinkingBlock: true`,
`outputPad: 0`) and a copy of your `auth.json` / `models-store.json`. Your own
extensions, packages and skills therefore never load into the test session.

| File | Checks |
| --- | --- |
| `suiteA.cjs` | expanding one summary shows its rows only; uniform row spacing; expanding does not change how many summaries exist; collapsing leaves nothing |
| `suiteD.cjs` | a `Thinking...` row expands to its text and collapses again |
| `suiteP.cjs` | expanding a bash row and collapsing the segment leaves no output rows |
| `suiteL.cjs` | `/reload` keeps one blank line between a summary and the following text |

`suiteL.cjs` needs `history-synthetic.jsonl`, generated by `make-history.cjs`
(12 rounds of thinking plus one call, then a final answer).

## Requirements

- `pi` on `PATH`, and Pi credentials in the config directory (the TUI tier
  makes real model calls).
- `node-pty` and `@xterm/headless`; `run-all` installs them into `tui/` on the
  first `--tui` run.

Assertions are structural (row numbers, presence of text), not screen snapshots,
so unrelated layout tweaks in Pi do not break them.

The TUI suites deliberately do not assume how many segments the model produces:
batching several calls without commentary between them is correct behavior, and
is one row of summary either way. Segment boundaries are covered
deterministically by `harness/segments.mjs` with synthetic messages.
